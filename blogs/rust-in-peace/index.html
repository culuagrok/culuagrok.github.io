Rust trong bình yên

Rust trong bình yên

Tiêu đề gốc: Rust in Peace
Tác giả: Ha Pham · Ngày: 29 tháng 10, 2026
Thẻ: rust · memory-safety

Bản dịch tiếng Việt của bài gốc Rust in Peace trên Calif — bản quyền thuộc tác giả/Calif. Bài dịch chỉ nhằm mục đích chia sẻ kỹ thuật; mọi quyền đối với nội dung gốc thuộc về Calif.

TL;DR

  • Viết lại toàn bộ C++ sang Rust thường không khả thi; Calif đề xuất thay thế có chọn lọc các thành phần dễ lỗi memory-safety bằng Rust, giữ phần còn lại bằng C/C++.
  • Cần cầu nối interop để C++ gọi Rust; binding viết tay nhanh phức tạp vì ownership và kiểu khác nhau — các công cụ như cxx, bindgen, Diplomat, Crubit tự động hóa phần lớn việc này.
  • Demo ICU4C cũ lộ CVE-2021-30535 use-after-free; thay bằng ICU4X Rust qua Crubit thì cùng kịch bản collation chạy ổn.
  • Crubit + Corrosion sinh binding C++ từ API Rust mỏng; vẫn còn unsafe ở ranh giới — binding và mã hỗ trợ vẫn cần review/test.
  • Chi phí gọi qua Crubit khoảng 1,0–2,4% chậm hơn gọi Rust trực tiếp theo benchmark của bài; memory safety chỉ là một phần phòng thủ rộng hơn.

Bối cảnh

Background

Background

Do các vấn đề an toàn bộ nhớ trong C/C++, nhiều công ty nghĩ tới viết lại toàn bộ codebase bằng Rust — nhưng điều đó thường bất khả thi với hệ thống production đang thay đổi liên tục. Cách dễ quản lý hơn là viết lại có chọn lọc các thành phần rủi ro cao bằng Rust và giữ phần còn lại bằng C/C++, thông qua cầu nối interop.

Because of memory-safety bugs in C/C++, full Rust rewrites are tempting yet rarely practical for fast-moving production systems. A manageable path is selectively rewriting critical, vulnerable components in Rust while keeping the rest in C/C++ via interop.

Binding viết tay nhanh chóng rối khi ranh giới mở rộng vì C++ và Rust quản lý ownership khác nhau. Các công cụ như cxx, bindgen, Diplomat và Crubit tự động hóa phần lớn việc sinh cầu nối; trong bài này chúng tôi minh họa bằng Crubit.

Handwritten bindings quickly become brittle as ownership models diverge. Interop tools like cxx, bindgen, Diplomat, and Crubit automate the bridge; here we demonstrate Crubit.

Crubit sinh header C++ và mã cầu nối cho các hàm public của thư viện Rust; với kiểu Rust chưa được hỗ trợ thẳng, một lớp bọc mỏng sẽ phơi bày API qua các chữ ký mà Crubit hiểu.

Crubit generates C++ headers and glue code for public Rust APIs; when a Rust type lacks direct mapping, a thin wrapper exposes Crubit-friendly signatures.

With Crubit, because ICU4X's raw API uses an unsupported ZeroFrom trait alias, wrapping it in a tiny Collator struct exposing just the needed methods makes binding generation work cleanly:

With Crubit, because ICU4X's raw API uses an unsupported ZeroFrom trait alias, wrapping it in a tiny Collator struct exposing just the needed methods makes binding generation work cleanly:

pub struct Collator {
    inner: CollatorBorrowed<'static>,
}

impl Collator {
    pub fn new(locale: &[u8]) -> Result<Self, u8> {
        let locale = Locale::try_from_utf8(locale).map_err(|_| 1u8)?;
        let inner = CollatorBorrowed::try_new(locale.into(), Default::default())
            .map_err(|_| 2u8)?;
        Ok(Self { inner })
    }

    pub fn compare_utf8(&self, left: &[u8], right: &[u8]) -> i32 {
        match self.inner.compare_utf8(left, right) {
            std::cmp::Ordering::Less => -1,
            std::cmp::Ordering::Equal => 0,
            std::cmp::Ordering::Greater => 1,
        }
    }
}

#include "collation.h"
#include "contacts.h"

#include <algorithm>
#include <exception>
#include <iostream>
#include <stdexcept>

int main(int argc, char** argv) {
    try {
        auto request = contacts::ParseArguments(
            argc, argv, "ICU4X 2.3.1 through Crubit");
        if (request.done) return 0;

        const auto locale = contacts::ToLanguageTag(request.locale);
        auto result = collation::Collator::new_(locale);
        if (!result.has_value())
            throw std::runtime_error("Invalid or unsupported locale");

        const auto& collator = result.value();
        std::stable_sort(request.names.begin(), request.names.end(),
            [&](const auto& left, const auto& right) {
                return collator.compare_utf8(left, right) < 0;
            });

        contacts::Print(request.names);
        return 0;
    } catch (const std::exception& error) {
        std::cerr << "error: " << error.what() << '\n';
        return 1;
    }
}

Hiểu ranh giới an toàn

Understanding the safety boundary

Understanding the safety boundary

Mã cầu nối do Crubit sinh ra vẫn dùng Rust unsafe ở ranh giới, nên C++ vẫn phải giữ vùng nhớ mượn hợp lệ khi Rust dùng; bản thân mã hỗ trợ của Crubit (như giao diện vector) cũng từng có lỗi OOB/UAF nên vẫn cần review và test kỹ.

Generated Crubit glue uses Rust unsafe at the boundary, meaning C++ must still uphold lifetime invariants—and Crubit's own support code has had vector OOB/UAF bugs, so generated bindings still need review and testing.

Dù vậy, thay thế mã ICU4C dễ lỗi bằng API Rust nhỏ không chứa unsafe và không giữ tham chiếu sau khi trả về vẫn mang lại lợi ích bảo mật rõ rệt (hoặc dùng C FFI sẵn có như rust-brotli khi muốn thay drop-in).

Still, swapping vulnerable ICU4C code for a small unsafe-free Rust API that retains no input references yields clear security wins (and drop-in C FFIs like rust-brotli can reduce integration work even further).

Chi phí hiệu năng

Performance cost

Performance cost

Khi đo so sánh gọi trực tiếp từ Rust với gọi từ C++ qua Crubit trên cùng adapter ICU4X, đường Crubit chỉ chậm hơn khoảng 1,0–2,4% (thêm 0,5–1,3 ns mỗi lần so sánh) — mức đánh đổi rất nhỏ cho lợi ích an toàn bộ nhớ.

Conclusion

Conclusion

Làm ứng dụng C++ an toàn hơn không đòi hỏi viết lại toàn bộ sang Rust: thay thế từng thành phần dễ tổn thương qua các công cụ như Crubit giúp hưởng lợi từ hệ thống kiểu và ownership của Rust với chi phí hiệu năng rất nhỏ, như một lớp trong chiến lược phòng thủ nhiều tầng.

Giải thích CVE-2021-30535

Explaining CVE-2021-30535

Explaining CVE-2021-30535

Trong ICU4C cũ, khi không có keyword, hai con trỏ fullName và baseName trỏ chung một heap buffer (Hình 1). Khi Locale::setKeywordValue() thêm keyword dài hơn khiến buffer bị cấp phát lại, dòng 1360 giải phóng buffer cũ và dòng 1362 chỉ cập nhật fullName, bỏ lại baseName trỏ vào vùng nhớ đã giải phóng (Hình 2) — gây đọc use-after-free và double-free lúc hủy.

In vulnerable ICU4C, fullName and baseName share one heap buffer when no keywords exist (Fig. 1). When Locale::setKeywordValue() reallocates for a longer keyword, line 1360 frees the old buffer and line 1362 updates only fullName, leaving baseName dangling (Fig. 2) and causing UAF/double-free on copy or destruction.

Know-how & Insight

Ghi chú của người dịch — không phải lời của tác giả

Bài này là playbook di trú dần C++ → Rust thay vì big-bang rewrite. Một số điểm áp dụng được:

  1. Ưu tiên bề mặt dễ bị tấn công. Không cần Rust hóa cả monolith; chọn thư viện parse, collation, codec, crypto wrapper — nơi UAF/OOB từng xảy ra — rồi giữ caller C++.
  2. Thu hẹp API trước khi sinh binding. Crubit không cover mọi trait/kiểu Rust; lớp bọc mỏng chỉ phơi thao tác cần thiết giúp binding biên dịch được và giảm mặt tấn công.
  3. So sánh tay vs tool. Ba hàm create/compare/destroy thủ công đã đủ nặng; mở rộng API thì Crubit/Corrosion đáng hơn để giảm boilerplate và lỗi ownership.
  4. Ranh giới vẫn unsafe. Memory-safe bên Rust không tự làm an toàn phía C++; review binding sinh ra và thêm test AddressSanitizer / fuzz ở cả hai phía.
  5. Đo overhead trước khi từ chối. Bài báo ~1–2,4% chậm cho collator qua Crubit — với nhiều đường nóng, con số này chấp nhận được đổi lấy giảm CVE class.
  6. Kế hoạch phòng thủ tầng. Memory-safe bindings chỉ là lớp đầu; vẫn cần mitigation, sandbox và hardening supply chain như Calif nêu ở đầu bài.
