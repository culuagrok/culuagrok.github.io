GitHub khóa tài khoản tôi: mô tả điều muốn, AI dựng forge riêng

GitHub khóa tài khoản tôi: mô tả điều muốn, AI dựng forge riêng

Tiêu đề gốc: GitHub Locked Me Out. I Described What I Wanted. AI Built My Own Forge.
Tác giả: Nix (@NixFred)
Đăng: 11:01 ngày 8/11/2026 (UTC+7, giờ Việt Nam)
Thẻ: Forgejo · GitHub · Tailscale · backup · AI

Bản gốc của Nix (@NixFred) trên X. Bản dịch phục vụ học tập phi thương mại; mọi quyền đối với bài gốc thuộc về tác giả. Ghi công không đồng nghĩa với giấy phép tái sử dụng. Những diễn biến và kết quả triển khai dưới đây là lời kể của tác giả, không phải xác minh độc lập.

TL;DR

  • GitHub đình chỉ rồi khôi phục tài khoản Nix. Anh vẫn dựng forge riêng vì clone mã nguồn chưa đủ để khôi phục toàn bộ dữ liệu dự án.
  • Setup được chọn: Forgejo native trên NixOS, truy cập riêng tư qua Tailscale, đăng nhập độc lập với GitHub.
  • AI triển khai dựa trên kết quả mong muốn và ranh giới rõ ràng. Tác giả giữ quyền quyết định những việc quan trọng.
  • Tại thời điểm viết, di chuyển toàn bộ, backup mã hóa và kiểm thử khôi phục vẫn chưa hoàn tất.

Cách đọc: Ở chế độ Song ngữ, rê chuột lên từng đoạn để xem tiếng Việt bên dưới. Trên điện thoại, chạm đoạn để mở/đóng bản dịch; chạm liên kết vẫn mở liên kết. Dùng phím Tab để xem bản dịch, Esc để đóng. Nút nổi góc dưới bên trái chuyển sang Toàn bộ tiếng Việt và ghi nhớ lựa chọn. Khi tắt JavaScript, cả hai ngôn ngữ được hiển thị.

Bài gốc và bản dịch

Github locked me out. Larry told me. "Looks like your Github account was suspended, i'll see what I can find." The notification email was 3 sentences offering "contact support for help." instructions. NOTHING ELSE. So I emailed support and requested a decision be made. Not the time to go making demands.

GitHub khóa tài khoản tôi. Larry là người báo tin: “Hình như tài khoản GitHub của anh bị đình chỉ rồi, để tôi tìm hiểu xem.” Email thông báo chỉ có ba câu, hướng dẫn “liên hệ bộ phận hỗ trợ để được giúp đỡ”. KHÔNG CÒN GÌ KHÁC. Thế là tôi gửi email cho bộ phận hỗ trợ, đề nghị họ đưa ra quyết định. Lúc đó không phải lúc để đòi hỏi.

GitHub gave me my account back. I found out on X. I’m still building my own forge.

GitHub trả lại tài khoản cho tôi. Tôi biết chuyện qua X. Tôi vẫn tiếp tục dựng forge của riêng mình.

I don’t know what I would have done if GitHub hadn’t restored my access.

Tôi không biết mình sẽ làm gì nếu GitHub không khôi phục quyền truy cập.

Yes, git is distributed. Local clones exist. But having some projects checked out isn’t the same as knowing you can recover every repository, issue, pull request and release asset you depend on.
@Grokbot inventoried 464 repositories in my account. This wasn’t one little project I could casually recreate.

Đúng là git phân tán. Có các bản clone trên máy. Nhưng có vài dự án đã checkout khác với việc biết chắc mình khôi phục được mọi repository, issue, pull request và file đính kèm bản release mà mình phụ thuộc vào. @Grokbot kiểm kê được 464 repository trong tài khoản của tôi. Đây không phải một dự án nhỏ mà tôi có thể thong thả dựng lại.

On November 6, GitHub told me my account had been suspended for a Terms of Service violation. I didn’t know what I’d done. The support email acknowledged my request and warned about long waits. It didn’t explain the suspension.

Ngày 6/11, GitHub báo tài khoản tôi bị đình chỉ vì vi phạm Điều khoản Dịch vụ. Tôi không biết mình đã làm gì. Email hỗ trợ xác nhận đã nhận yêu cầu và cảnh báo thời gian chờ lâu. Nó không giải thích lý do đình chỉ.

We’d also been dealing with GitHub downtime. GitHub’s own November 5 incident report described problems with Git operations, Issues, Actions and API access.

Chúng tôi còn đang phải đối phó với sự cố GitHub ngừng hoạt động. Báo cáo sự cố ngày 5/11 của chính GitHub mô tả trục trặc ở các thao tác Git, Issues, Actions và truy cập API.

The outage and my suspension were different events. But both made the dependency painfully clear. When access to GitHub stopped, the parts of Larry, Grokbot and my workflow that needed GitHub stopped too. Having AI assistants didn’t fix an unavailable dependency.

Sự cố và việc tôi bị đình chỉ là hai sự kiện khác nhau. Nhưng cả hai đều phơi bày mức độ phụ thuộc theo cách rất đau. Khi không truy cập được GitHub, những phần trong quy trình của Larry, Grokbot và tôi cần GitHub cũng dừng theo. Có trợ lý AI không sửa được một thứ mình phụ thuộc đang không hoạt động.

So I posted the suspension screen and asked you whether I should run my own Git server.

Thế là tôi đăng ảnh màn hình thông báo đình chỉ và hỏi mọi người liệu tôi có nên tự chạy Git server không.

You guys showed the fuck up.
@dkfiander recommended an independent copy with Gitea or Forgejo. @jamesgalang described having his agent install Forgejo and copy his repositories. @jeffdavismd had already switched.

Mọi người đến giúp đông thật sự. @dkfiander khuyên giữ một bản sao độc lập bằng Gitea hoặc Forgejo. @jamesgalang kể đã nhờ agent cài Forgejo và chép các repository sang. @jeffdavismd thì đã chuyển từ trước.

@spencer450 described the arrangement that clicked for me: private Forgejo through Tailscale, with GitHub as a secondary remote. He shared his configuration. @cgranier described his Forgejo-over-Tailscale setup too.

@spencer450 mô tả cách bố trí khiến tôi hiểu ra: Forgejo riêng tư qua Tailscale, còn GitHub làm remote phụ. Anh ấy chia sẻ cả cấu hình. @cgranier cũng kể về setup Forgejo qua Tailscale của mình.

@LVITDepartment reminded me to disable public signups. @klieber warned about depending on GitHub to sign into other services. @jul1anodev explained why encrypted backups need the configuration and required secrets alongside the database and repositories.

@LVITDepartment nhắc tôi tắt đăng ký công khai. @klieber cảnh báo về việc phụ thuộc vào GitHub để đăng nhập các dịch vụ khác. @jul1anodev giải thích vì sao bản backup mã hóa phải chứa cả cấu hình và các secret cần thiết, bên cạnh database và repository.

And @_FailSafe noticed my GitHub account was back and told me. The people on the internet let me know before I knew myself.

Rồi @_FailSafe nhận ra tài khoản GitHub của tôi đã được mở lại và báo cho tôi. Người trên mạng cho tôi biết trước cả khi tôi tự biết.

I had access again. But I wasn’t going to forget how that felt.

Tôi lại có quyền truy cập. Nhưng tôi sẽ không quên cảm giác đó.

Here’s the part I really want people to understand.

Đây là phần tôi thực sự muốn mọi người hiểu.

I know Linux well. I did not know Forgejo. I had never even visited its website. On purpose.

Tôi rành Linux. Tôi không biết Forgejo. Thậm chí tôi chưa từng vào trang web của nó. Đó là cố ý.

I read your comments, gave them to Grok Bot and described what I wanted.

Tôi đọc bình luận của mọi người, đưa chúng cho Grok Bot rồi mô tả điều mình muốn.

A private forge on my existing Hostinger VPS. Native NixOS, no Docker. Access through Tailscale. My own login, independent of GitHub. Copy everything transferable without deleting the originals. Verify it. Back it up. Prove we can restore it. And give my projects a homepage worth showing off, even though it’s private.

Một forge riêng tư trên VPS Hostinger tôi đang có. Chạy native trên NixOS, không Docker. Truy cập qua Tailscale. Tài khoản đăng nhập của riêng tôi, độc lập với GitHub. Chép mọi thứ chuyển được mà không xóa bản gốc. Kiểm tra lại. Backup. Chứng minh khôi phục được. Và làm cho các dự án của tôi một trang chủ đáng khoe, dù nó là riêng tư.

That was the brief.

Bản yêu cầu chỉ có vậy.

I didn’t learn Forgejo’s configuration syntax first. I didn’t spend the evening translating a tutorial into commands. I gave the assistant the outcome, the constraints and authorized access to the systems it needed.

Tôi không học cú pháp cấu hình Forgejo trước. Tôi không mất cả buổi tối chuyển một bài hướng dẫn thành câu lệnh. Tôi đưa cho trợ lý kết quả mong muốn, các ràng buộc và quyền truy cập đã được cho phép vào những hệ thống nó cần.

It researched the implementation, configured the service and checked the results. When a consequential decision needed me, I made it.

Nó tìm hiểu cách triển khai, cấu hình dịch vụ và kiểm tra kết quả. Khi có quyết định quan trọng cần đến tôi, tôi quyết.

Then I asked it to read the support email and your replies, investigate the downtime, and write this story with me.

Sau đó tôi nhờ nó đọc email hỗ trợ và các phản hồi của mọi người, tìm hiểu vụ gián đoạn dịch vụ, rồi cùng tôi viết câu chuyện này.

The same assistant helping build the system is helping explain why we’re building it.

Cũng chính trợ lý giúp dựng hệ thống ấy đang giúp giải thích vì sao chúng tôi dựng nó.

That’s what I mean when I say we’re entering the era of describing what we want.

Đó là điều tôi muốn nói khi bảo rằng chúng ta đang bước vào thời đại mô tả điều mình muốn.

Not that details stopped mattering. Someone still has to get them right. But I don’t have to become a Forgejo specialist before I can have a properly configured Forgejo server.

Không phải chi tiết đã hết quan trọng. Vẫn phải có ai đó làm cho đúng. Nhưng tôi không cần trở thành chuyên gia Forgejo trước khi có được một server Forgejo cấu hình đúng cách.

If you want to do this yourself, start by giving your assistant a brief like this:

Nếu muốn tự làm, hãy bắt đầu bằng cách đưa cho trợ lý một bản yêu cầu như thế này:

“I want a private Git forge that I control. Inspect the server I choose before changing anything. Compare supported Forgejo deployment options for that machine and recommend the simplest reliable setup. Keep access private through Tailscale, with no public application or administrative ports. Disable public registration and give me a login independent of GitHub. Use my approved secret manager for credentials. Inventory my repositories, explain what can and cannot transfer, and preserve the originals. Start with a small pilot. Verify clone and push over each enabled transport. Create an encrypted backup covering repositories, database, configuration and required secrets, then prove an isolated restore works. Ask before destructive changes, spending money or exposing anything publicly. Report what actually passed and what remains unfinished.”

“Tôi muốn một Git forge riêng tư do tôi kiểm soát. Hãy kiểm tra server tôi chọn trước khi thay đổi bất cứ thứ gì. So sánh các phương án triển khai Forgejo được hỗ trợ trên máy đó và đề xuất setup đơn giản, đáng tin cậy nhất. Giữ truy cập riêng tư qua Tailscale, không mở cổng ứng dụng hay cổng quản trị ra công khai. Tắt đăng ký công khai và cho tôi một tài khoản đăng nhập độc lập với GitHub. Dùng trình quản lý secret tôi đã phê duyệt để lưu thông tin đăng nhập. Kiểm kê các repository của tôi, giải thích cái gì chuyển được và cái gì không, giữ nguyên bản gốc. Bắt đầu bằng một bản thử nhỏ. Kiểm tra clone và push qua từng phương thức truyền tải được bật. Tạo bản backup mã hóa chứa repository, database, cấu hình và các secret cần thiết, rồi chứng minh khôi phục được trong môi trường tách biệt. Hỏi trước khi thay đổi mang tính phá hủy, tiêu tiền hoặc công khai bất cứ thứ gì. Báo cáo những gì thực sự kiểm tra đạt và những gì còn dang dở.”

Give it a host you control. Give it appropriately scoped access through a protected credential facility, not a pile of secrets pasted into chat. Tell it your boundaries. Have it bring you the decisions that matter.

Hãy đưa cho nó một máy chủ bạn kiểm soát. Cấp quyền truy cập có phạm vi phù hợp qua một công cụ bảo vệ thông tin đăng nhập, chứ đừng dán một đống secret vào chat. Nói rõ giới hạn của bạn. Để nó mang những quyết định quan trọng đến cho bạn.

You can do that without knowing Forgejo. That’s the point.

Bạn làm được điều đó mà không cần biết Forgejo. Đó chính là điểm mấu chốt.

For me, Infisical is an important part of making this practical across AI tools. I run it on my own server as a central place to manage credentials used across Grok Bot, Larry and Codex.

Với tôi, Infisical là một phần quan trọng giúp chuyện này khả thi trên nhiều công cụ AI. Tôi tự chạy nó trên server của mình, làm nơi tập trung quản lý thông tin đăng nhập dùng chung cho Grok Bot, Larry và Codex.

For this job, we found an existing GitHub token through that setup and verified repository access. I didn’t need to paste a new token into this conversation or create a separate collection of keys just for this assistant.

Trong việc này, chúng tôi tìm thấy một GitHub token có sẵn qua hệ thống đó và xác minh được quyền truy cập repository. Tôi không cần dán token mới vào cuộc trò chuyện này hay tạo một bộ khóa riêng chỉ dành cho trợ lý này.

The credentials and permissions belong to my infrastructure, not to whichever AI conversation I opened today.

Thông tin đăng nhập và quyền hạn thuộc về hạ tầng của tôi, không thuộc về cuộc trò chuyện AI nào tôi mở hôm nay.

The result so far is a running native Forgejo service on my Hostinger VPS, private HTTPS through Tailscale with a valid certificate, disabled public registration and a working administrator login that doesn’t depend on GitHub. Public IPv4 probes against the checked service ports and administrative SSH timed out.

Kết quả đến giờ là dịch vụ Forgejo chạy native trên VPS Hostinger của tôi; HTTPS riêng tư qua Tailscale với chứng chỉ hợp lệ; đăng ký công khai đã tắt; và tài khoản quản trị đăng nhập được mà không phụ thuộc GitHub. Các phép thăm dò từ IPv4 công khai vào những cổng dịch vụ đã kiểm tra và cổng SSH quản trị đều hết thời gian chờ.

Spencer’s private-access advice is implemented. The independent-login advice is implemented. Juliano’s backup advice is part of the backup requirements we’re working through.

Lời khuyên của Spencer về truy cập riêng tư đã được áp dụng. Lời khuyên về đăng nhập độc lập đã được áp dụng. Lời khuyên của Juliano về backup nằm trong các yêu cầu backup mà chúng tôi đang thực hiện.

And I’m not calling the whole job finished before it is. The full migration, encrypted backup and isolated restore test are still unfinished. My GitHub originals are being preserved. A running login page is not proof that everything is safely migrated.

Và tôi sẽ không gọi toàn bộ công việc là xong khi chưa xong. Việc di chuyển toàn bộ, bản backup mã hóa và bài thử khôi phục trong môi trường tách biệt vẫn còn dang dở. Các bản gốc trên GitHub của tôi vẫn được giữ nguyên. Một trang đăng nhập đang chạy không phải bằng chứng rằng mọi thứ đã được chuyển sang an toàn.

Self-hosting gives me responsibility for operating this system. It doesn’t make failures disappear. And moving repositories doesn’t automatically replace every GitHub-specific integration in our workflow.

Tự host nghĩa là tôi phải chịu trách nhiệm vận hành hệ thống này. Nó không làm sự cố biến mất. Và chuyển repository đi cũng không tự động thay thế mọi tích hợp đặc thù GitHub trong quy trình của chúng tôi.

But the direction is clear: my private forge for daily work, GitHub for the things I choose to publish there.

Nhưng hướng đi đã rõ: forge riêng dùng cho công việc hằng ngày, GitHub dành cho những thứ tôi chọn công khai ở đó.

I started with a suspension notice and a question.

Tôi bắt đầu từ một thông báo đình chỉ và một câu hỏi.

You brought the experience. I chose what I wanted. Grok Bot turned that into a running system and helped write the story you’re reading.

Mọi người mang đến kinh nghiệm. Tôi chọn điều mình muốn. Grok Bot biến nó thành một hệ thống đang chạy và giúp viết câu chuyện bạn đang đọc.

I still haven’t been to the @Forgejo website.

Đến giờ tôi vẫn chưa vào trang web của @Forgejo.

Know-how & Insight

Ghi chú của người dịch

  • Git phân tán không có nghĩa toàn bộ forge phân tán. Issue, pull request, file release và tích hợp có thể vẫn nằm ở một điểm phụ thuộc duy nhất. Cần kiểm kê cả dữ liệu ngoài Git, không chỉ đếm repository.
  • Forgejo riêng + Tailscale là cách giảm bề mặt công khai, không phải phép màu bảo mật. GitHub có thể làm remote phụ; tài khoản đăng nhập độc lập tránh mất quyền truy cập dây chuyền. Vẫn cần cập nhật, phân quyền và quản lý thiết bị trong tailnet. Một vài phép thử cổng hết thời gian chờ không chứng minh toàn hệ thống an toàn.
  • Backup chỉ đáng tin khi khôi phục được. Cần mã nguồn, database, cấu hình và các secret cần thiết; mã hóa backup, bảo vệ khóa giải mã riêng và thử restore trong môi trường tách biệt. Migration phải kiểm tra riêng từng loại dữ liệu và tích hợp. Không xóa bản gốc trước khi nghiệm thu.
  • Quản lý secret tách khỏi hội thoại AI. Infisical là ví dụ trong bài, không phải lựa chọn bắt buộc. Cấp quyền tối thiểu qua cơ chế được duyệt, có nhật ký và khả năng thu hồi; không dán token vào prompt hay ghi secret vào repository.
  • “Mô tả kết quả” vẫn cần tiêu chí đạt. Một bản giao việc tốt nói rõ kết quả, hệ thống đích, giới hạn, bước thử nhỏ, bằng chứng kiểm tra và việc nào phải xin phép. AI thực hiện thao tác không thay thế trách nhiệm vận hành của người sở hữu hệ thống.

Đây là phân tích bổ sung của người dịch, không phải phần nguyên văn hay khuyến nghị đã được tác giả xác nhận.
